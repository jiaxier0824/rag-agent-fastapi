# 真实集成测试摘要

> 本文只公开可复现实验配置与聚合指标；不包含课程原始文件、转写文本、用户会话、API Key 或服务日志。

## 运行环境

- 本机 Docker Compose：RAG、Agent、MySQL、Redis 四服务。
- 知识库规模：4 个课程领域、30 份 Markdown 文档、860 个 Chroma 向量切片。
- 检索链路：向量 Top-5、BM25 Top-5、RRF 融合 Top-6、`qwen3-rerank` 精排 Top-3。
- RAG 生成模型：`qwen-turbo`。
- Agent 主 / 备用模型：`qwen-turbo` / `qwen-plus`。

## 首次问答结果

使用 15 道跨课程问题、每题独立 session 进行测试，以避免 Redis 缓存影响首次检索结果。

| 指标 | 结果 |
|---|---:|
| HTTP 问答成功率 | 15 / 15（100%） |
| 来源命中率 | 14 / 15（93.33%） |
| 平均端到端耗时 | 5.73 秒 |
| 中位端到端耗时 | 5.77 秒 |
| 最快 / 最慢 | 3.89 秒 / 9.94 秒 |

“来源命中”表示接口返回的来源文件包含人工标注的预期资料，衡量检索可追溯性；它不替代人工的事实正确性审核。唯一未命中样例被保留为后续查询改写和切片策略优化用例。测试期间 Rerank 保持开启。

## Redis 入口缓存验证

对同一个课程问题、同一个 `session_id` 连续请求两次：

| 请求 | 端到端耗时 | 运行结果 |
|---|---:|---|
| 第一次 | 12.03 秒 | `qwen-turbo` 调用 Agent 工具与独立 RAG 服务 |
| 第二次 | 44.6 毫秒 | `model_used=cache`、`rag_cache_hit=true`，跳过 Agent 和 RAG 调用 |

缓存键使用用户原始 `question + session_id`，而非模型可能改写的工具参数，避免同一问题因工具参数重述而失去缓存命中。
